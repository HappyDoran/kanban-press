# ADR 0002: 칸반 상태를 저장하지 않고 Notion과 블로그 저장소에서 계산

- 상태: Accepted
- 결정일: 2026-11-11
- 대체: AGENTS.md 고정 아키텍처의 "사용자별 칸반은 브라우저 IndexedDB에 저장한다"

## 맥락

칸반의 표시 여부·순서·구조 판별 캐시를 브라우저 IndexedDB에 두었더니, 같은 GitHub 계정으로
다른 브라우저에서 로그인하면 칸반이 달랐다. 새 브라우저는 최상위 page만 보여 주므로 하위 page나
database 행으로 게시한 글은 블로그 저장소에 있어도 게시 완료 열에 나타나지 않았다.
[ADR 0001](0001-db-adoption-gate.md)은 여러 기기 간 칸반 동기화를 DB 도입 gate로 두었다.

## 결정

동기화하지 않고 동기화할 상태를 없앤다. 칸반은 열 때마다 다음으로 계산한다.

- 카드: 선택한 Notion 연결의 page 중 하위 page가 없는 문서 page 전부. Notion 수정 시각이 최근인 순서.
- 역할: 하위 page(직접 자식, database 행, 토글 안 page)가 있으면 컨테이너. 토글 안 page는 목록을 만들 때
  서버가 block의 부모를 거슬러 올라가 소유 page를 찾는다(목록 한 번에 최대 50회 조회).
- 게시 완료: 블로그 저장소에 그 page ID 접미사의 글 파일이 있는지.
- 게시 중·실패 안내: 화면 메모리.

## 결과

- DB도 동기화도 없이 같은 계정이면 어느 브라우저에서나 칸반이 같다. ADR 0001의 gate는 열리지 않는다.
- 칸반에서 카드 표시·숨김(✕, 문서 목록의 추가 버튼)과 보관 중 순서 바꾸기가 없어진다. 칸반에 올릴 문서는
  Notion 연결의 page 공유 범위로 고르고, 보관 중 열은 제목 검색으로 좁힌다.
- 화면에 보이는 page마다 outline을 읽던 자동 구조 판별이 없어져 Notion 호출이 줄어든다. outline은 문서
  목록에서 page를 펼칠 때만 읽는다. 하위 page 없이 `link_to_page`만 있는 page는 이제 문서로 본다.
- 칸반은 선택한 연결 하나의 문서만 보여 준다.
- 사용자 브라우저에 남은 옛 IndexedDB(`kanban-press.board.<ID>`)는 읽지도 지우지도 않는다.
