# nkb-spec-discovery

요구의 정본은 docs/spec/PROJECT_SPEC.md 하나다. docs/planning/ 문서는 제안·감사 기록이며 확정된 요구는 제품 명세로 옮긴다. 결정이 사용자의 몫인 것은 대신 정하지 않는다.

1. 문제와 사용자를 한두 문장으로 쓰고 근거가 있으면 출처를 붙인다. 근거가 없으면 가설로 표시한다.
2. 범위를 가장 작은 검증 가능한 단위로 정한다. 하고 싶은 기능은 지우지 않고 MVP 밖 항목과 도입 조건(예: ADR 0001의 DB 도입 gate)으로 옮긴다.
3. 새 요구에는 기존 R1~R7 다음 번호를 붙인다. 완료 조건은 다른 작업자가 검증 명령이나 화면 확인으로 판정할 수 있게 쓴다.
4. 외부 제공자·OAuth scope·비용·법적 동의처럼 사용자만 정할 수 있는 것은 gap-analysis 미결 결정에 선택지와 막는 단계를 적고 질문한다.
5. 범위가 정해지면 docs/spec/gap-analysis.md 백로그를 단계로 나누고 요구사항 번호를 연결한다.
6. 범위를 바꿀 때는 이유와 영향받는 백로그 단계를 함께 고친다. 요구를 조용히 줄이지 않는다.
